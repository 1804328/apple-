# 个人软件技术路线（可复用 Playbook）

> 从 `strong-reminder` 项目沉淀出来的一套打法。适用于「个人工具类产品 + 轻后端」：
> 移动 App、需要本地能力（通知/闹钟/相机/传感器）、需要跨设备或定时任务兜底。
> 如果你的新软件是 Web / 桌面 / 小程序 / 脚本，先看第 0 节的形态判断。

---

## 0. 先做三个判断（决定后面 80% 的选型）

### 0.1 形态判断

| 形态 | 适用 | 框架 | 分发 |
|---|---|---|---|
| **iOS/Android App** | 需要系统能力（闹钟、通知、后台、蓝牙） | Expo (React Native) | 免费签名 / 开发者账号 |
| **Web 应用** | 纯信息管理、无系统能力 | Next.js / Vite | Cloudflare Pages（免费） |
| **桌面工具** | 需要本机文件/进程 | Tauri（Rust+Web）或 Electron | 直接装 exe |
| **微信小程序** | 用户都在微信、不愿装 App | 原生小程序 / Taro | 微信审核 |
| **命令行/脚本** | 自己用、自动化 | Node / Python | 无 |

**教训**：形态选错，后面所有工程努力都在补锅。先问「这件事是否真的需要 App」——很多需求 PWA + 云端定时器就够，能省掉签名、审核、7 天重签全部麻烦。

### 0.2 「强制力」判断（如果产品核心是提醒/打断）

各平台的硬边界必须先查清，否则规划全是空中楼阁：

| 能力 | iOS | Android |
|---|---|---|
| 静音/勿扰下响铃 | iOS 26+ AlarmKit | 通知渠道绕过 DND（需权限） |
| 抢占全屏 | ❌ 系统不允许 | ✅ 全屏 Intent（受商店政策限制） |
| App 被杀后仍触发 | ✅ AlarmKit / 本地通知 | ✅ AlarmManager 精确闹钟 |
| 无法关闭 | ⚠️ 只能靠 App 内验证页 + 连环闹钟 | ✅ 可做 |
| 跨静音兜底 | 短信 / 电话 / 微信 | 同 |

**结论**：iOS 上「绝对强制」不存在，只能做「高摩擦 + 多通道升级」。别向用户承诺"关不掉"。

### 0.3 自建 vs 买

先花 1 小时用现有产品（竞品 2–3 个）走一遍主流程。如果现有产品能覆盖 80%，自建的价值只剩「数据自主 + 可定制」，要诚实评估是否值得 2 周工期。

## 1. 需求与验收（半天，别跳过）

产出物：
1. **一页用户故事**：谁、在什么场景、要解决什么、失败会怎样
2. **验收清单**：可逐条打勾的行为，例如
   - 静音+专注+锁屏+杀进程，四种叠加下是否响
   - 关机 2 小时后开机是否补发
   - 断网时本地是否仍工作
   - 重装后数据能否恢复
3. **明确的硬边界**：把第 0.2 节查到的平台限制写进文档，避免后期返工
4. **非目标**：明确不做什么（省掉 50% 的复杂度）

## 2. 技术选型（默认答案，可直接抄）

### 2.1 客户端

| 方案 | 什么时候选 | 风险 |
|---|---|---|
| **Expo (React Native) + TypeScript** | 默认。双端一套代码，Windows 可开发，EAS/GitHub Actions 云构建 | 原生模块要 prebuild，改动需重建 |
| Flutter | 团队会 Dart、UI 一致性要求高 | 同样需要云构建 |
| 原生双端 | 系统能力极深（如真正的系统级闹钟） | 工作量 ×2 |

**默认组合**：Expo SDK（最新稳定）+ RN + TS strict。
**不要加的东西**：导航库（页面少就用状态切换）、UI 组件库（自写 20 个组件更可控）、状态管理库（一个 Context + AsyncStorage 够）。

### 2.2 后端

| 方案 | 成本 | 适用 |
|---|---|---|
| **Cloudflare Workers + D1** | 免费额度足够个人 | 默认。Cron + HTTP + SQL 都有 |
| Supabase | 免费档 | 需要 Auth / 实时 / 存储 |
| 国内函数计算（腾讯云/阿里云） | 有免费额度 | 国内访问要求高、Worker 域名被墙 |
| 自建 VPS | ¥30–60/月 | 需要长连接、WebSocket |

**默认组合**：Worker（路由 + Cron）+ D1（SQL）。代码用纯 ESM，单文件入口 + 少量模块，避免打包复杂度。

### 2.3 通知/推送通道（按到达率排序）

| 通道 | 成本 | 备注 |
|---|---|---|
| 本地通知/闹钟 | 0 | 主通道，离线可用 |
| APNs / FCM | 0 | App 被杀时的补充 |
| 企业微信群机器人 | 0 | 国内最稳的免费"强通道" |
| WxPusher | 0 | 进个人微信 |
| PushPlus | 已收费 | 别依赖 |
| 短信（阿里云/腾讯云） | ~¥0.04/条 | 商用主力，需签名模板 |
| 电话语音 | ~¥0.1/次 | 最高强制力，做成付费档 |

**教训**：免费第三方推送服务随时可能商业化或关停，通道必须做成**适配器**（一个 `send()` 接口 + 一个注册表），换服务只改一个文件。

### 2.4 数据存储

- 客户端：AsyncStorage（本地优先，离线可用）
- 云端：D1（SQLite 语法），表结构简单、加字段用迁移文件
- **双写原则**：本地立即落盘 → 后台同步云端；读取以本地为主，云端只做恢复和统计

## 3. 开发环境（Windows + iPhone 的标准配置）

| 需求 | 方案 | 成本 |
|---|---|---|
| iOS 编译 | 无 Mac：**GitHub Actions macOS runner** 出未签名 IPA；有预算：EAS Build | 免费（公开仓库不限） |
| 装到 iPhone | **Sideloadly + 免费 Apple ID**（7 天有效）；长期用：¥688/年开发者账号 | 免费 / ¥688 |
| iOS 依赖管理 | EAS 代管证书、App ID、描述文件 | 免费 |
| 安卓 | 直接装 APK，无需签名体系 | 0 |
| 下载 GitHub 加速 | SSH over 443（`ssh.github.com:443`），绕过 HTTPS 被墙 | 0 |

**GitHub Actions 构建链**（本项目的做法，可复用）：
1. `macos-26` runner（Xcode 26，支持 iOS 26 SDK）
2. `npm ci` → `npx expo prebuild --platform ios --no-install`
3. `pod install`（失败自动 `--repo-update` 重试）
4. `xcodebuild -workspace *.xcworkspace -scheme <自动解析> -configuration Release -sdk iphoneos CODE_SIGNING_ALLOWED=NO`
5. 打包 `Payload/` → `unsigned.ipa` → upload-artifact
6. 失败时打印错误摘要（grep `error:`），不要让人翻 500 行日志

**踩过的坑，直接抄结论**：
- 镜像里有多个 Xcode，**默认版本才有 iOS 平台组件**；按版本号选 newest，失败自动换版本重试
- 构建产物名/ scheme 名不确定 → 动态解析，不要写死
- 每次构建 7–10 分钟，**攒一批改动再推**，不要改一行推一次

## 4. 工程实践（防崩三件套）

这三条是本项目真实踩坑换来的，任何 RN 项目都适用：

### 4.1 Hook 顺序

所有 `useState/useEffect/useMemo/useCallback` 必须写在**任何 early return 之前**。
否则会出现 `Rendered more hooks than during the previous render`，真机直接闪退。

### 4.2 错误边界

在 App 最外层包一个 `ErrorBoundary`，渲染出错时显示错误文本而不是闪退。
**真机没有控制台，错误边界是你唯一的排错窗口。**

### 4.3 并发与响应

- **乐观更新**：点击后立即改本地状态并返回，排闹钟/网络请求放后台
- **操作锁**：同一 key 的操作执行期间忽略重复触发（防连点重复提交）
- 不要 `await` 网络后才做 UI 跳转

## 5. 云端最小骨架

```
server/
├─ wrangler.toml         # name / main / [triggers] crons / [[d1_databases]] / [vars]
├─ schema.sql            # CREATE TABLE IF NOT EXISTS
├─ migrations/001_*.sql  # 每次加字段一个文件
├─ deploy.ps1            # 一键：建库→建表→部署→写 secret→回填域名→再部署→健康检查
├─ src/
│  ├─ index.js           # fetch 路由 + scheduled（Cron）
│  ├─ lib/db.js          # 所有 SQL
│  ├─ lib/<domain>.js    # 纯函数（必须可单测）
│  └─ channels/          # 通道适配器：push.js / wecom.js / wxpusher.js
└─ test/                 # node --test（纯函数 + 路由冒烟）
```

必备端点：
- `GET /health`（存活 + 配置自检）
- `POST /api/test`（用当前配置的通道发一条测试消息，排障神器）
- 业务 CRUD
- `GET /a/<token>`（一次性确认链接，无鉴权，token 即凭证）

**Cron 是灵魂**：所有「到点没做就升级」的逻辑都放 Cron，客户端只负责"当下打扰"，云端负责"没反应就催"。

## 6. 观测与排障（没有这些你会瞎猜）

| 手段 | 用途 |
|---|---|
| `/health` + `/api/test` | 确认链路与通道是否配置正确 |
| 直接查 D1（Cloudflare API `/d1/database/{id}/query`） | 看数据到底写没写、投递结果 ok/error |
| `deliveries` 表记录每次投递 | 通道失败原因一眼可见（如"企微 404"= webhook 失效） |
| App 内错误边界 + 设置页「最近同步时间」 | 判断是本地问题还是云端问题 |
| 设置页「通道自检」按钮 | 用户自己就能确认兜底链是否工作 |

**教训**：排障能力要在功能设计阶段就预留，而不是出问题后加。

## 7. 分发与运维

### 免费签名（无开发者账号）

- 有效期 7 天，到期 App 打不开 → 提醒全哑
- 用产品自己设一条「每周重签」提醒（本项目就这么做的）
- **重装会清库** → 所以必须有「从云端恢复」功能，否则每周都要重录数据

### 什么时候买 ¥688/年

连续用满一个月、或开始把「绝对不能漏」的事交给它时。买之前的所有设计（云端恢复、多通道）**都不浪费**。

### 版本追踪

每次构建绑定一个 commit sha；产物有效期 30 天；出问题先看是哪次构建引入的。

## 9. 新项目 7 天启动计划

| 天 | 做什么 | 产出 |
|---|---|---|
| D1 | 需求 + 平台硬边界调研 + 竞品试玩 | 一页需求 + 验收清单 |
| D2 | 技术验证 spike：**只验证最危险的 3 件事**（原生能力、构建链、外部通道） | 三个能跑的最小 demo |
| D3–D4 | 本地优先的骨架：数据模型 + 主流程 UI + 本地存储 | 能离线用的版本 |
| D5 | 云端骨架：路由 + 表 + Cron + 一个通道 | 端到端能收到一条通知 |
| D6 | 构建链 + 真机安装 | 手机上跑起来 |
| D7 | 验收清单逐条过 + 错误边界/观测补全 | 可交付 |

**关键**：D2 的 spike 一定要先做。本项目就是先验证 AlarmKit + 云构建 + 通道，才避免后面返工。

`strong-reminder` 仓库里这些模块基本与业务无关，改改就能用：

| 路径 | 作用 |
|---|---|

**复用方式**：复制整个仓库 → 删业务页面 → 保留骨架、CI、Worker、签名流程。

## 11. 一句话总结

> **先验证最危险的平台能力，再用「本地优先 + 云端兜底」的骨架把链路跑通，最后才做体验打磨。**
> 原生依赖和构建链是最大风险，纯 JS 能解决的就不要上原生。
